Method

How the model separates architectural truth from what the initiator can see

The simulator is an AXI/AoU-inspired transaction model over specification-derived UCIe recovery behavior. It records the target’s commit count and, separately, the completion the initiator actually received.

The complete AoU 0.8 text was not available to the model-building workspace. AoU packing and credit behavior are explicit abstractions. The cited link-down activation rule is the normative AoU behavior used by the model. This is not a full AoU 0.8 conformance implementation.

Event model

Time is a sequence of protocol events. The 375-flit replay timeout, the 128-flit sequence-number handshake bound, the 8 ms sideband timeout, and the 16 ms LinkError residency are single events in the model. They are not wall-clock delays. The CRC LFSR in the specification is not executed. One-, two-, and three-bit flips are treated as detected because UCIe §3.7 guarantees detection of up to three bits. The replay-count limit defaults to 3. Section 3.8 points at the PCIe rules for speeds at or below 32 GT/s and does not restate that integer, so the model keeps it as a parameter.

A transaction moves through logical phases. A fault may be armed at one of them:

  1. Created, then accepted locally on AXI.
  2. AoU request packed and the request flit transmitted.
  3. Request received by the remote endpoint.
  4. Write data accepted locally, packed, transmitted, and received remotely. Reads skip these phases.
  5. Target accepts the operation.
  6. Target commits. This is the architectural effect.
  7. Write response created, packed, transmitted, and received.
  8. Transaction completed at the initiator.

The device model commits a write only after both the request and the write data have been delivered. It does not commit on the address alone. Early write response is off unless a scenario turns it on. Both choices are device-model assumptions. AoU and UCIe do not define the device’s commit point.

The model is intentionally event-accurate rather than cycle-accurate because the primary property is an observability and reachability property: whether two different architectural outcomes can produce the same observer-visible state. Cycle-accurate modeling would be needed for quantitative real-time claims such as worst-case recovery latency, deadline violations, arbitration effects, or a precise ambiguity duration in nanoseconds.

Link paths

UCIe behavior is taken from Revision 2.0, Version 1.0 (6 August 2024), and, for the second model, from Revision 3.0, Version 1.0 (5 August 2025). A 2.0 rule is used in the 3.0 model only where the 3.0 text still states it. The implemented rules are named in simulation/model/ucie.py and simulation/model/spec30.py.

The paths include CRC failure and replay instead of delivery of an invalid flit, the retry threshold leading to Retrain, LinkReset, and LinkError. LinkError cleanup flushes retry buffers and pipelines. The cited AoU 0.8 §8.3.3 rule returns the activation FSM to DISABLED on FDI link-down. Retrain is not that event, and the model leaves AoU enabled across Retrain. After reset, the link returns to Active, the sequence-number handshake completes, AoU activation completes, and credits are initialized to depth 4 in each direction.

UCIe 3.0 mechanisms are modeled only to the extent the 3.0 text defines them: sideband performant mode, priority sideband opcode, Fast Throttle, Emergency Shutdown, runtime recalibration, and runtime parity. The priority-packet payload is left to a future ECN, so the model records opcode only and does not invent a transaction encoding. None of those mechanisms, as modeled, supplies a standardized indication of the associated AXI transaction’s architectural commit state. The classifier refuses a commit bit the specification text used here does not define. Emergency Shutdown is modeled as rapid containment of a severe condition, not as a transaction-completion mechanism.

Two records

Ground trutharchitectural_commit_count = 1
Initiatorcompletion_received = false
ResultUNKNOWN

Ground truth is the number of times the target applied the operation. Initiator state is whether AXI accepted the transaction and whether an OKAY completion was delivered. The label is computed from the initiator state and from the observation profile. The commit count is consulted only by the later invariant checks.

COMPLETED requires OKAY at the initiator. NOT_COMPLETED, under FDI and AXI alone, is a transaction the manager has not handed to the endpoint. After handoff, a missing completion is UNKNOWN. An explicit UNKNOWN response from policy C is UNKNOWN. It is not OKAY, and it is not permission to retry.

Policies

UCIe does not say which AXI completion an outstanding transaction receives after LinkError. The model does not invent one silent answer. Policy in simulation/model/types.py is the choice.

Named policies. Definitions follow the repository README.
Policy Meaning
A · DISCARD Discard outstanding AoU transactions. No AXI completion.
B · PRESERVE_LOCAL If a completion already sat in the initiating AoU, deliver it after cleanup.
C · EXPLICIT_UNKNOWN Return an explicit UNKNOWN to the software model. Not OKAY, and not permission to retry.
D · AUTO_RETRY Automatically retry the same logical transaction after the link is up.
E · NO_AUTO_RETRY Do not retry automatically. Same initiator-visible result as A in this model.

What the classifier may read

Observation profiles. Retry disposition is an assumption, not a standardized profile.
Profile Facts available
1 · FDI / AXI AXI was accepted, OKAY was or was not received, and a destructive link event occurred. This is the recovery interface the model treats as defined for the protocol layer: pl_state_sts, plus whatever AXI response was already delivered.
2 · Software error Profile 1, plus link and D2D error registers. Those registers name CRC, Retrain, and LinkError conditions. They do not name an AXI transaction.
3 · Management Profile 2, plus management-transport status, Link Health Monitor, and, on UCIe 3.0, Fast Throttle, Emergency Shutdown, and priority-sideband opcode. None of the structures this model reads carries a standardized AXI architectural-commit indication.
Retry disposition ACK/NAK history latched before the retry buffer is flushed. Sections 3.8 and 10.3.3.5 do not require that history to survive, or to be tied to an AXI id. Using it is an assumption.

The classifier is not allowed to let profiles 2 and 3 invent a different FDI/AXI label. A true commit bit would mean the model had invented a field the specification text used here does not define. On the reported equivalence pairs, all three standardized profiles match. That match is a simulation result for those pairs, not a proof that every added UCIe 3.0 register is irrelevant to reliability.

Fault injection

The systematic suite walks named scenarios, including a fault at each relevant phase of the watched transaction. The randomized suite draws 200 injections with seed 1. Faults include bit corruption, repeated corruption of a replay, retry timeout and threshold, forced Retrain, LinkReset, and LinkError, dropped request or response, and the UCIe 3.0-only indications. The position tables in the results use the phase at which the watched transaction’s fault fired, grouped into five buckets from “before target acceptance” through “after response delivery”.

AoU packing is one message per flit. Credits are one per message, not per granule. The complete AoU 0.8 text was not available to the model-building workspace, so this is not a full AoU 0.8 conformance implementation. Those packing and credit choices are labeled abstractions in simulation/model/aou.py. The cited §8.3.3 link-down rule is the normative AoU behavior the model uses.
