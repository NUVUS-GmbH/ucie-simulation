Limitations

Scope of the result

The study shows that transaction-fate ambiguity is reachable under the modeled, specification-consistent assumptions. It does not measure a silicon link, and it does not assign the rates below the status of protocol probabilities.

Model and specifications

  • The simulation is an abstract protocol model, not a silicon implementation. It is not a PHY, and it is not cycle-accurate. Time is a sequence of protocol events.
  • AoU 0.8 is under development. The AoU 0.8 specification text is not in this workspace. The only AoU rule treated as normative is the publicly cited §8.3.3 behavior: FDI link-down returns the activation FSM to DISABLED and drops an in-flight Activate or Deactivate handshake. Retrain does not.
  • Some behavior is implementation-defined and modeled as explicit policy. Outstanding AXI fate after LinkError cleanup is a policy. The threshold algorithm for Retrain is implementation specific. The replay-count integer is a parameter, because §3.8 points at the PCIe recommendation and does not restate the integer.
  • Packing is one message per flit. Credits are one per message, not per granule. Initial credit depth in the printed traces is 4. The on-wire credit encoding is not modeled.
  • The CRC LFSR is not executed. Detection of one-, two-, and three-bit corruption follows the §3.7 guarantee. The millisecond and flit-count thresholds are single events, not wall-clock delays.
  • UCIe link behavior and AXI architectural commit semantics are modeled at different abstraction levels. The device commits a write only after the request and the write data have been delivered. That is a device-model assumption. Early write response is off unless a scenario turns it on.

What the numbers mean

  • Randomized percentages depend on the fault workload and seed. The published random suite uses seed 1 and 200 injections. A different seed or a different mix of fault positions would move the rates.
  • Reachability results are stronger than statistical rates. UNKNOWN is reachable in both revisions on the equivalent workload. That claim does not depend on treating 48.8% or 69.4% as a property of UCIe.
  • The study does not prove that every implementation will exhibit the same outcome. An implementation can latch more local history than UCIe requires, preserve a response that policy A discards, or add an end-to-end commit log. Those are outside the standardized facts this classifier is allowed to read.
  • The study shows that the ambiguity is reachable under the modeled, specification-consistent assumptions. Where the text is silent, the model uses a named policy rather than an invented completion.

UCIe 3.0 mechanisms

  • Priority sideband payload details are left to a future ECN. The model records opcode only. It does not invent a transaction encoding inside a priority packet.
  • Fast Throttle and Emergency Shutdown are optional. Emergency Shutdown is fatal and can be left only by reset. The specification, as used here, does not define a log of outstanding mainband transactions, so the model does not add one.
  • Sideband performant mode removes a 32 UI gap. This model counts logical protocol events, not UI. The shorter gap is not turned into a fate event.
  • Higher line rates, 48 GT/s and 64 GT/s, do not add an end-to-end transaction acknowledgement in the text the model uses. The model does not treat a higher rate as a change to transaction fate.

This study does not claim that UCIe is incorrect. It identifies a cross-layer recovery gap between link-level recovery semantics and transaction-level architectural knowledge.
