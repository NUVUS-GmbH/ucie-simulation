UCIe / AoU FAULT-INJECTION STUDY

An Interrupted AXI Transaction Can Have an Indeterminate Architectural Outcome

In the modeled UCIe recovery scenarios, a committed operation with lost completion and an operation that never reached the target both receive UNKNOWN under the implemented observer/classifier.

The ground-truth outcomes differ; the implemented fate classifications match. This does not establish equality of the complete observer-visible histories or that richer diagnostics cannot determine fate. The study uses the classifications COMPLETED, NOT_COMPLETED, and UNKNOWN. UNKNOWN is a study classification, not a UCIe-defined protocol state.

PROBLEM

The problem

UCIe can detect and recover from communication failures. However, a higher-layer transaction may already have changed architectural state before its completion response becomes visible to the initiator.

Nominal path

  1. AXI request
  2. transport
  3. target accepts
  4. architectural commit
  5. response

Ambiguity window

  1. architectural commit
  2. FAULT
  3. response not observed

Did the operation execute?

The study classifies interrupted transactions as COMPLETED, NOT_COMPLETED, or UNKNOWN. These are observer-dependent study labels, not UCIe-defined protocol states.

different architectural outcome+same implemented fate classification=transaction-fate ambiguity

INTERPRETATION

Why this matters

Consider a non-idempotent write that increments a shared counter:

counter = 7

write increments counter

If the operation committed

7 → 8

but the response was lost, blind retry can produce:

8 → 9

Outcome

expected commits = 1
actual commits = 2
Blind retry can convert uncertainty into duplicate execution.

This applies to non-idempotent operations, including doorbells, DMA start, accelerator start, FIFO push, interrupt acknowledge, and actuator-related commands.

RESULT

Cross-client timing effects

Independent traffic sources sharing the same UCIe transport resources can influence each other's timing. Client A carries the injected faults; Client B is otherwise fault-free. No hypervisor or guest isolation model is established here.

cross-client added delay ≈ 44 ns

The effect remained observable with multiple outstanding flits and realistic buffering. Client B commits once and completes.

INTERPRETATION

Automotive interpretation

Automotive relevance arises when safety-critical commands cross a shared chiplet transport path.

A system-level safety architecture must decide how to handle an operation whose architectural effect cannot be reconstructed after recovery.

  • Reset a fault-containment region
  • Mark the operation as indeterminate
  • Use persistent transaction IDs
  • Use duplicate suppression
  • Use device-specific recovery contracts

This study does not claim an ISO 26262 violation. Cross-client timing coupling is architecture- and policy-dependent evidence for system architects, not a normative freedom-from-interference finding.

INTERPRETATION

What this study claims

Strongly supported: the measured commit counts, UNKNOWN classifications, and blind-retry duplicate execution. Supported with qualification: reachability persists under the reference configuration and current classifier.

  • A committed operation with lost completion and a non-committed operation both receive UNKNOWN under the implemented observer/classifier.
  • These outcomes remain reachable with reference-configured FIFOs, retry buffering, credits and multiple outstanding flits, under the implemented classification policy.
  • Blind retry of an indeterminate non-idempotent operation can duplicate its effect.
  • The current classifier leaves modeled diagnostic information unused; the experiments do not establish the limits of richer diagnostic classifiers.
  • Some timing coupling between independent traffic sources remains under the reference configuration.
  • Some simulator outcomes are implementation-dependent.
Not yet established: full observational equivalence of the traces, or that richer UCIe diagnostics cannot resolve transaction fate.
INTERPRETATION

What this study does not claim

  • UCIe is broken.
  • UCIe violates its specification.
  • Every UCIe implementation behaves this way.
  • The reference configuration fully specifies a commercial implementation.
  • The timed SystemC model is cycle-accurate to real silicon.
  • The measured timing numbers are universal.
  • Cross-client interference automatically implies an ISO 26262 freedom-from-interference violation.
  • UCIe is responsible for defining AXI target commit semantics.
ASSUMPTION / SCOPE

Limitations

  • Abstract target model: architectural commit is modeled, not silicon-verified.
  • Incomplete knowledge of commercial UCIe controller microarchitecture.
  • Configurable recovery policies (for example, outstanding AXI discard after LinkError).
  • Timed SystemC, not transistor-level or cycle-accurate to commercial IP.
  • No silicon validation; no RTL or commercial IP confirmation.
  • Random workload rates are not field probabilities.
  • The reference architecture is not a complete implementation specification.
  • The AoU model remains an abstraction where the full specification behavior is not modeled.
  • Format-6 optional bytes, electrical training, and FDI cycle accuracy are out of scope.
  • Diagnostic fields are study abstractions, not standardized or vendor register maps.
  • Finite scenarios establish reachability, not exhaustive absence of other outcomes.
  • The timed equivalence flag checks fate labels and completion status, not complete observer-visible histories.
  • Profiles B/C do not use all recorded diagnostic state for classification; a stronger diagnostic classifier has not been evaluated.

INTERPRETATION

Conclusion

The study demonstrates that recovering a UCIe link and reconstructing the architectural fate of an interrupted higher-layer operation are different problems. In the reference-architecture model, a committed non-idempotent operation whose response is lost and an operation that never reached the target both receive UNKNOWN under the implemented observer/classifier. Blind retry of the committed case can create duplicate architectural effects. Full observer-history equivalence and the ability of richer diagnostics to resolve fate remain untested stronger claims.

The reference configuration shows that this ambiguity is not dependent on a one-flit transport simplification. At the same time, model refinement exposed other behaviors as implementation-dependent. The next step is validation against a concrete UCIe controller implementation.
