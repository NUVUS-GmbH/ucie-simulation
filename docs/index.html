Transaction-Fate Ambiguity Survives Reference-Architecture Validation

A timed SystemC model with reference-configured buffering, credits, retry state, and multiple outstanding flits reproduces the original AXI transaction-fate ambiguity.

We first identified an AXI transaction-fate ambiguity in an abstract fault model. We then removed major transport simplifications and re-ran the experiments using the provided UCIe D2D reference configuration. The central ambiguity remained reachable.

RESULT

Cross-client timing effects

Client B completion latency, measured from transaction creation. Client A carries the injected faults; both share the modeled adapter/link. No hypervisor or guest isolation model is established here.

The effect did not disappear when the single-in-flight assumption was removed. Reference latency increases from 46 to 90 ns. Client B commits once and completes.

CONFIG Reference experimental timing budget = 55.2 ns (46 × 1.20); faulted latency exceeds it. The previous model used 73.2 ns (61 × 1.20). Neither is an automotive-standard deadline.

INTERPRETATION The effect is architecture- and policy-dependent; it is not a universal UCIe timing property or, by itself, an ISO 26262 freedom-from-interference violation.

Why the reference-model delay persists

Shared resource: adapter replay scheduling and the go-back-N sequence domain.
Exact trace events and timestamps

Client B transmits while several flits are outstanding, then its request is discarded twice while the receiver awaits the expected sequence. Replay is scheduled ahead of new payload in the adapter. This supports coupling through the shared replay path; it does not support attributing B’s delay to a single occupied TX slot.

The 2019–2043 ns interval spans observed sequence waiting and subsequent delivery, not a measured pure-wait counter. The trace does not decompose all 44 ns of added latency. Retrain at 2104 ns happens after B completes and cannot explain that completion delay.

INTERPRETATION

What this study claims — and does not claim

Supported claims

  • Transaction-fate ambiguity is reachable in the executable model.
  • The ambiguity survives a more detailed UCIe D2D reference architecture.
  • Blind retry of an indeterminate non-idempotent operation can duplicate architectural effects.
  • Additional transport diagnostics do not necessarily reveal target commit.
  • Timing coupling between independent traffic sources survives multiple outstanding flits in the tested configuration.
  • Refinement identifies the original retry-buffer peak of one as a model artifact.

Not claimed

  • UCIe is broken or violates its specification.
  • Every commercial UCIe implementation behaves this way.
  • The reference slide fully specifies a real product microarchitecture.
  • The timed model is cycle-accurate to commercial IP.
  • Measured nanosecond values are universal UCIe timings.
  • The experimental deadline is an automotive-standard deadline.
  • Cross-client latency automatically proves an ISO 26262 freedom-from-interference violation.
  • UCIe is responsible for defining AXI architectural commit semantics.

ASSUMPTION / SCOPE

Limitations

  • No RTL, electrical PHY, or commercial IP validation; no transistor-level equivalence.
  • Format-6 optional bytes, electrical training, and FDI cycle accuracy are out of scope.
  • AoU 0.8 specification text is absent from this workspace; packing and credits include explicit abstractions.
  • Diagnostic fields are study abstractions, not standardized or vendor register maps.
  • L1 nesting with concurrent recovery commands uses a single command slot.
  • The reference diagram constrains parameters, not every microarchitectural or recovery decision.
  • Finite scenarios establish reachability; they do not establish field failure rates or exhaustive absence of other outcomes.

INTERPRETATION

The next step is implementation validation.

The initial transaction-fate ambiguity was not eliminated by replacing simplified transport assumptions with a more detailed UCIe D2D reference architecture. The refined model reproduced committed-but-unacknowledged UNKNOWN, blind-retry duplicate execution, and observational equivalence for limited observers.

Refinement also exposed retry-buffer occupancy of one as a model artifact. The study separates findings that survived refinement from implementation-dependent behavior, rather than treating every simulator outcome as a protocol property.

The next step is to determine which remaining behaviors occur in a concrete UCIe D2D controller and which are resolved by proprietary microarchitecture or system-level recovery policy.
